# Workout product recovery audit

Reference: [the requested openGym repository](https://github.com/arvids-unavailable/openGym/tree/c42ba6b98e3776af5981f20c05ba392238799670), `main` = `c42ba6b98e3776af5981f20c05ba392238799670`, verified with `git ls-remote` on 2026-10-04. Local inspected checkout: `workout_tmp/requested-reference`. The newer DuarteSantos8 checkout is **not** the specification for this audit.

This audit supersedes the **product-parity conclusions** of WORKOUT_AUDIT.md and WORKOUT_AUDIT_MATRIX.md. Their historical test results remain historical evidence, not proof of matching visuals or interactions. No overall parity percentage is justified yet. Dataset identity, functional coverage, visual structure, and interaction flow are assessed separately. `PARTIAL` includes implemented behavior with materially different UI/UX or incomplete verification. A screen's existence never establishes parity.

The first inspection below precedes recovery code changes. Source paths in the reference column are relative to its `frontend/src/`. SIRVYA paths prefixed `W/` mean `lib/screens/ENG/workout/`; `B/` means `backend/`. "Existing tests" means tests were read, not rerun during this audit. Exact visual equivalence has not been established by matched reference/native screenshots.

## Architecture and file inventory

- Entry points: `lib/screens/ENG/clientHome.dart`, `lib/mainLayoutCoach.dart`, `lib/components/ENG/coachNavbar.dart`; `backend/index.js` mounts `/api/workout` with existing JWT authentication. The separate `lib/premium` and `premiumWorkouts.js` flows are older premium features, not this recovery's target.
- Screens/widgets: all 18 Dart files under `lib/screens/ENG/workout/`, including Home, builder, library/details, active session, set rows, progress/history/editor, charts, check-in, preferences, tools, balance, muscles, media/demonstrations, transfer and PDF.
- Models/services: `lib/models/workout.dart`, `lib/models/workout_demonstration.dart`, `lib/services/workout_service.dart`, `workout_recovery.dart`, `workout_timer.dart`; shared `apiService.dart`, `notification_service.dart`, localization and theme services.
- Backend: `routes/anas/workout.js`; `services/workoutDomain.js`, `workoutExperience.js`, `workoutQueries.js`, `workoutStats.js`, `workoutImport.js`, `workoutHistoryTransfer.js`, `workoutReminders.js`, `workoutMedia.js`, `workoutMediaCleanup.js`; existing `weightHistory.js` and `middleware/auth.js`.
- Persistence/data: `config/workoutSchema.js`; `migrations/2026_sirvya_workout.sql`, `2026_workout_experience.sql`, `2026_workout_audit_indexes.sql`; `data/exerciseMetadata.json`, `workoutExercises.js`, `workoutDemonstrationSources.json`; `assets/workout/demonstrations/`, bundled fonts and `pubspec.yaml`. Dataset remains intact; no import rerun is needed for parity recovery.
- QA: eight `test/workout*_test.dart` suites plus widget/navigation tests; seven `backend/tests/workout.*.test.js` suites; `backend/scripts/verifyWeb.mjs`, schema/repository audits and historical `docs/verification/` artifacts.

Actual data model: plans contain reusable routine days; routine slots prescribe values; active sessions snapshot prescriptions, retain execution revisions and actual set rows. Date overrides live separately from weekday assignments. Recovery/outbox keys are account-scoped. Coach access uses existing `coachclients`, not openGym admin identities. These are useful foundations to retain.

## Recovery order and verification gates

1. Restore Home/Plan separation and Workout navigation; add real dated Home bodyweight/goal/streak, contextual date overrides, and a weekly-assignment flow. Preserve Client/Coach authorization and program identity.
2. Correct library search/facet semantics and direct routine selection. Preserve dataset IDs and licensed demonstrations; do not download excluded media.
3. Replace the default single-set/all-card presentation with focused exercise/superset grids. Correct prior-value precedence, unit-boundary rest, ±15-second controls, and automatically completed timed sets with explicit early-Done/cancel.
4. Match progression rules with source-linked fixtures, retaining separate original Coach prescriptions. Audit actual-load progression, double rep range, timed deload, and per-side/bodyweight reset.
5. Close Stats/history/chart/calendar/import/editor interaction differences; compare native/reference captures at matched sizes/data before upgrading visual status.

Tests must assert behaviors that distinguish the implementations: searching equipment/description; switching equipment without dead ends; prior set 3 falling back to last set; weight in pounds on charts; timed deadline versus early finish/cancel; no rest after completed superset; source/destination date overrides leave weekday program unchanged. Test pass is recorded separately from UI/UX status.

License boundaries: current third-party notices permit existing metadata and reviewed replacement demonstrations. Reference code is AGPL; this recovery uses independently authored Flutter/backend code. The dataset media exception is a row-level blocker, not justification for excluding Workout functionality. No release/license conclusion is inferred from this source audit.
